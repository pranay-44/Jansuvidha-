# Deploying JanSuvidha on Oracle Cloud Infrastructure

Use one OCI Compute VM for Caddy and Node. Keep the existing MySQL schema. A public DNS hostname and a VM are needed only when deploying. Confirm the region, plan, backups and expected cost before creating resources.

1. Point a DNS A record at the VM's reserved public IPv4 address. Allow inbound TCP 80 and 443 in the OCI network security group and host firewall. Restrict SSH to the operator. Keep Node on loopback and MySQL on loopback or a private network. For a remote MySQL server use verified TLS and configure the CA trust chain.
2. Install Node 22.13 or newer at /usr/bin/node, Caddy, and a supported MySQL server/client. Create a non-login service user and group named jansuvidha. Put this checkout in /opt/jansuvidha and run npm ci --omit=dev there. The web assets are tracked in dist.
3. Prepare /etc/jansuvidha.env with restricted read permissions. Start from deploy/oci/service.env.example. Set NODE_ENV=production, HOST=127.0.0.1, PORT=4173, APP_ORIGIN=https://your-hostname, PRESENTATION_MODE=false and ALLOW_LOCAL_STAFF_WITHOUT_MFA=false. Generate independent random SESSION_SECRET and MFA_ENCRYPTION_KEY values. Use 32 random bytes encoded as 64 hex digits for the MFA key. Keep an encrypted backup of that key with restricted access. Set database credentials, SMTP and at least one citizen OAuth provider. Register the exact HTTPS callback from SOCIAL_AUTH_SETUP.md. Use a limited runtime database account and separate migration credentials.
4. Back up the database. From the checkout, run node --env-file=/etc/jansuvidha.env scripts/migrate.mjs with migration privileges. Set up the first administrator with node --env-file=/etc/jansuvidha.env scripts/auth-cli.mjs bootstrap. From a private interactive terminal run node --env-file=/etc/jansuvidha.env scripts/enroll-staff.mjs for each active staff member. Verify the person's identity first and have them confirm a code from their authenticator. For a lost phone use the same identity-verified enrollment procedure. It revokes the previous factor and sessions. Password reset does not replace a factor.
5. Install jansuvidha.service in /etc/systemd/system. Copy Caddyfile to /etc/caddy/Caddyfile and replace the hostname placeholder with your DNS hostname, or set JANSUVIDHA_DOMAIN in Caddy's systemd environment. Run caddy validate --config /etc/caddy/Caddyfile with that environment. Run systemctl daemon-reload, enable and start jansuvidha.service, then reload/start Caddy. Caddy obtains and renews the public certificate once DNS and ingress work.
6. Open the HTTPS site in a phone browser. Test the citizen OAuth round trip, staff password plus authenticator sign-in, encrypted session cookies, and an offline write followed by reconnect. Verify the item from a second signed-in device and verify isolation with another account. Check GPS permission prompts and routing on the actual phone. Perform a database/key restore drill before accepting real citizen data.

When building the Android bundle set JANSUVIDHA_PUBLIC_ORIGIN to the same HTTPS origin before npm run android:sync. The offline map remains available in the app. The account link opens the hosted service in the system browser so OAuth and cookies use the same origin. Device-only records in the Android WebView and system browser have separate storage.
